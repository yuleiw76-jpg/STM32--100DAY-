## Hello画面与当前源码的区别

当前main.c先蓝色填屏、显示Hello，然后进入仍启用的RGB快填屏循环。用户明确确认：**照片是在调试时暂停循环，源码没有改。**

因此，照片验证了暂停时的显示状态；继续运行会被后续填屏覆盖。归档保留本人确认的源码，不把它改成持续静止显示Hello的版本。

本次Hello为16号字、非叠加模式，前景WHITE、背景BLUE，坐标(0,40)。其他字号、叠加和触摸不据此视为通过。

## 配置与数据量

| 项目 | 本次配置/计算 |
| --- | --- |
| MCU / 总SRAM | STM32F103C8 / 20KiB |
| SPI | SPI1主机，1LINE，8位，MSB First，CPOL=0、CPHA=0 |
| 分频 / 标称SCK | 4分频，ioc计算18Mbit/s；未实测波形 |
| NSS/CS、SCK、MOSI | PA4、PA5、PA7 |
| RES、DC | PB10、PB11 |
| 横屏 | USE_HORIZONTAL=2，480×320 |
| 像素数据 | 153600像素×2字节=307200字节=300KiB，命令等另计 |
| 分块 | 128像素/256字节缓冲，整屏1200批像素数据 |
| 栈预留 | Stack_Size EQU 0x400，即1024字节，未修改 |

分块减少发送调用次数，数据总量不变。用户体感更快，但没有耗时、帧率或提速倍数；1200是批次，不是加速倍数。

局部缓冲256字节不等于函数总栈开销；函数调用等也需要空间。本次没有测量栈峰值，回收栈空间也不保证旧内容清零。
