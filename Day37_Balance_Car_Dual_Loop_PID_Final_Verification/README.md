在 MPU6050、DMP、编码器、PWM、电机方向和串口遥测均正常的基础上，完成直立环与速度环的联合调试。小车已经能够落地立住，因此本阶段调试正式结束。

## 核心控制结构

控制任务运行在 TIM1 更新中断中：

- 每 1 ms 进入一次中断并采样编码器输入；
- 每 5 ms 读取一次 DMP 数据并执行直立环；
- 每 10 ms 计算一次编码器速度并执行速度环；
- 电机输出由直立环和速度环加权合成。

```text
MPU6050 DMP -> Pitch -> Upright PD ----+
                                        +-> Motor Mix -> TIM4 PWM -> L298N
Encoder -> Speed -> Speed P -----------+
```

## 最终参数

### 直立环

```c
static float P = 300;
static float I = 0;
static float D = 0.70;
float aim_pitch = 1.3f;
```

### 速度环

```c
static float P = -500;
static float I = 0;
static float D = 0;
float aim_v = 0;
```

当前速度环只使用 P 控制。实验中启用积分后出现持续累积和输出饱和，因此最终版本暂时保持 `I = 0`。

### 双环权重

```c
#define ax 0.05  // Speed loop
#define bx 1.0   // Upright loop
```

合成公式：

```c
pid_out = bx * upright_output + ax * speed_output;
```

## 最终验证结果

在最终参数下完成约 10 秒落地测试，采集 449 组串口数据：

- Pitch 范围：约 `-1.165° ~ 4.086°`
- Pitch 平均绝对误差：约 `1.491°`
- Pitch 位于目标角 `±3°` 的比例：`100%`
- 直立环输出饱和比例：`0%`
- 轮速范围：约 `-0.513 ~ 0.641 r/s`
- 平均绝对轮速：约 `0.094 r/s`
- 轮速接近零的比例：`97.6%`
- 速度环输出范围：约 `-256.4 ~ 320.5`
- 速度环输出饱和比例：`0%`
- 实物现象：小车能够落地立住，两侧车轮同步纠偏

以上数据说明当前直立环具备稳定纠偏能力，速度环能够抑制短时间位置漂移，并且两个控制环均未长时间进入输出限幅。

## 主要调试记录

### 1. MPU6050 与 DMP

- 早期使用的兼容模块返回 `WHO_AM_I = 0x70`，需要针对兼容芯片修改判断。
- 更换真正的 MPU6050 后，`WHO_AM_I = 0x68`。
- DMP 固件加载、FIFO 数据读取和 Pitch 输出均已验证。

### 2. 编码器无数据

现象：`TIM2->CNT`、速度值和编码器边沿计数基本不变化。

原因：编码器没有连接 3.3V 和 GND。

修复：补齐编码器供电和共地后，A/B 相边沿与 TIM2 计数恢复正常。

### 3. 速度计算跨零异常

原速度公式直接把整圈数和当前计数值相加，TIM2 计数跨零时会产生接近 `100 r/s` 的假速度。

修复后先把整圈数换算成每圈 1560 个编码器计数，再与当前计数差相加：

```c
speed = -(float)(((circle_count1 - last_count) * 1560)
        + ((int)TIM2->CNT - last_CNT)) / 1560.0f / 0.01f;
```

### 4. 速度积分饱和

现象：速度环输出长时间固定在 `+2000` 或 `-2000`，同时加重车身振荡。

测试：关闭速度积分并降低速度环 P，比较 Pitch、轮速和输出饱和比例。

结论：当前结构下速度积分累积过快。将速度环调整为 `P=-500、I=0` 后，轮速和双环输出恢复稳定。

### 5. 硬件接触不良

调试过程中多次遇到面包板、STM32、电源、GND 和串口线松动。连接不稳会表现为：

- MPU6050 初始化失败；
- 串口没有数据；
- 编码器无计数；
- 模块突然灭灯；
- 复位后状态不一致。

因此本项目最终结论是：控制算法已经跑通，但第一代硬件只适合作为学习和验证原型，不适合继续进行高强度参数优化。

## Learning Summary

这次平衡小车项目让我完整经历了一个闭环控制系统从无法运行到实物验证成功的过程：

1. 验证传感器身份和 I2C 通信；
2. 使用 DMP 获取稳定的 Pitch；
3. 检查电机和编码器的正负方向；
4. 单独调整直立环 PD；
5. 修复编码器测速公式；
6. 逐步接入速度环；
7. 通过串口统计误差、轮速和输出饱和比例；
8. 最终让小车落地立住。

本阶段最大的收获是：嵌入式控制不能只看 PID 参数。供电、共地、接触可靠性、采样周期、方向、单位、限幅和测试方法都会直接决定最终效果。
