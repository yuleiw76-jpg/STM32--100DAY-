# Day32_MPU6050_Attitude_Data_Stability_Diagnosis

## 1. 今日学习内容

今天继续调试 STM32 两轮平衡小车，但没有直接增加直立环的 `P` 或加入 `D`，而是优先检查 MPU 姿态数据是否可靠。

在水平静置、重新固定模块以及多次复位测试中，发现 `Pitch` 有时可以恢复到合理范围，有时却会长时间停留在约 50°，甚至出现大范围跳变。同时还出现过 DMP 初始化时间较长、偶尔初始化失败的现象。

因此今天的重点从“PID 参数调节”转为“MPU6050 姿态数据稳定性诊断”。

## 2. 当前硬件与工程状态

当前平衡小车使用：

- STM32F103C8T6
- 标注为 MPU6050 的兼容 IMU 模块
- 软件 I2C
- DMP 姿态解算
- L298N 电机驱动
- 两路直流减速电机

当前模块读取到的身份信息为：

```text
I2C address: 0x68
WHO_AM_I:    0x70
```

`0x68` 是当前 I2C 设备地址，而 `0x70` 是寄存器 `0x75` 的 `WHO_AM_I` 返回值，两者不能混为一谈。当前工程已经针对该返回值按 MPU6500 兼容方式运行。

## 3. 今日观察到的现象

### 3.1 正常状态

重新按正并固定 MPU 模块后，部分测试中：

- `Pitch` 能够回到接近水平位置的合理数值；
- 静止时角度变化较小；
- 摇动车身后姿态角能够随动作改变；
- DMP 可以完成初始化。

### 3.2 异常状态

在另外几次相同水平放置条件下，又出现：

- `Pitch` 长时间保持在约 50°；
- 水平静止时姿态角仍大范围跳变；
- 同一次测试中角度可能从正常突然变为异常；
- DMP 初始化耗时变长，偶尔不能正常完成；
- 复位后结果不完全一致。

这些现象说明当前输入数据不具备稳定的可重复性。

## 4. 排查思路

今天按照以下逻辑进行判断：

```text
现象：水平静止时 Pitch 偶发大幅异常
→ 假设：模块安装、接触、供电、I2C 通信或芯片兼容性存在问题
→ 测试：重新固定模块、保持车身静止、多次复位并连续观察 Pitch
→ 观察：有时恢复正常，有时仍然严重异常
→ 结论：暂时不能把问题归因于 PID，必须先解决姿态输入不稳定
```

目前尚不能仅凭视频确定是芯片本体损坏。可能原因包括：

1. MPU 模块或杜邦线接触不稳定；
2. 模块固定不牢，测试过程中发生机械偏移；
3. 供电或地线受到电机系统干扰；
4. 当前兼容芯片与原 MPU6050 DMP 教程代码仍存在差异；
5. 模块本身质量或内部传感器状态异常。

以上仍属于待验证原因，不能直接视为最终故障结论。

## 5. 为什么今天暂停 PID 调参

直立环的输入来自 `Pitch` 和 `gyro[1]`：

```c
err = aim_pitch - Pitch;
pidp = P * err - D * gyro[1];
```

如果真实车身接近水平，而 `Pitch` 错误地显示为 50°，控制器会把它当成严重倾倒并输出很大的电机控制量。此时无论怎样调整 `P` 和 `D`，得到的实验现象都不能真实反映参数效果。

因此必须遵守以下顺序：

```text
姿态数据稳定
→ 正负方向正确
→ 机械平衡角确认
→ 电机纠偏方向正确
→ 再进行 P、D 参数调节
```

DMP 初始化成功只代表初始化流程通过，并不自动证明后续每一帧姿态角都可靠。

## 6. 今日决定

为了避免继续在不稳定的传感器输入上浪费调参时间，决定购买一块能够明确验证以下条件的 GY-521 MPU6050 模块：

```text
寄存器地址：0x75
WHO_AM_I：   0x68
```

购买时优先选择已焊排针、卖家能够提供实测结果、评论中有 STM32 或 DMP 使用记录的模块。当前返回 `0x70` 的模块暂时保留，后续可以作为兼容模块研究或备用件。

## 7. 新模块到货后的验证计划

新模块到货后不立即安装到小车，先在桌面完成最小系统验证：

1. 只连接 STM32、MPU6050 和 J-Link；
2. 确认寄存器 `0x75` 连续读取均为 `0x68`；
3. 连续复位 5～10 次，确认每次都能完成初始化；
4. 水平静置 1～2 分钟，观察 `Pitch` 是否稳定；
5. 分别前倾、后倾，确认角度变化方向正确；
6. 确认 `gyro[1]` 静止时接近零，转动时能正确响应；
7. 验证通过后再固定到车体，并重新测量机械平衡角；
8. 最后继续直立环 PD 调参。

更换为真正返回 `0x68` 的 MPU6050 后，需要同步检查工程中的芯片宏定义和 `WHO_AM_I` 判断，不能直接沿用当前针对 `0x70` 兼容模块的配置。

## 8. 今日结论

今天没有继续追求让小车立即站立，而是发现了比 PID 参数更基础的问题：姿态输入偶发不可信。

已确认：

- 当前模块的 `WHO_AM_I` 为 `0x70`；
- `Pitch` 在部分测试中可以正常变化；
- 相同水平静置条件下也可能出现明显异常；
- 当前数据稳定性不足以继续有效调参。

尚未确认：

- 异常是否完全由 MPU 模块本体造成；
- 是否还存在接触、供电干扰或 DMP 兼容性问题；
- 更换模块后能否彻底消除异常。

## 9. Learning Summary

今天最大的收获是认识到：平衡小车的 PID 控制效果建立在可靠传感器数据之上。编译通过、DMP 初始化成功、变量能够变化，都不等于数据已经可以用于闭环控制。

嵌入式调试需要先保证输入可信，再分析算法和输出。遇到小车无法平衡时，不能只盯着 `P`、`I`、`D`，还要验证传感器身份、静态稳定性、安装状态、通信可靠性和供电环境。
