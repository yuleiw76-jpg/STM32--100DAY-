## 2. 硬件、软件与显示的分工

```text
RTC 时钟源 → 分频 → 硬件秒计数
秒中断 → RTC_Get() → 把计数换算为 calendar 的年月日时分秒
主循环 → 读取 calendar 和分频器 → 串口打印
```

STM32F1 本例的 calendar 是软件结构体，不是硬件自动存放的完整年月日。主循环里的 delay_ms(100) 主要影响打印间隔；若中断被屏蔽或延迟，软件结构体刷新可能落后，但不能把它与硬件计数停止混为一谈。

vu8/vu16 分别是 volatile 的 8/16 位无符号类型。成员在中断中修改、主程序读取时，volatile 用于表达这类异步访问要求。它不提供整组字段的原子快照，也不禁止所有优化。变量仅在普通顺序执行的函数之间传递，不因此自动需要 volatile。

## 3. 为什么选择 LSI，具体改了什么

用户板上看到的 8.00 主晶振通常是 8 MHz HSE，不是手册所选的 32.768 kHz LSE；没有仅凭正面照片断定板上绝对不存在其他晶振。本次由用户明确选择 LSI 上电实验，不再追查 LSE 硬件。

| 改动 | 原因 |
| --- | --- |
| 开启 LSI、等待 LSIRDY、选择 RTC 的 LSI 来源 | 不依赖外接 LSE；原工程等待 LSE，不会自动回退到 LSI |
| 标称频率 40000、PRL=39999 | RTC 分频除数是 PRL+1，标称 40000/(39999+1)=1Hz，实际频率未测量 |
| 毫秒字段改用同一组 LSI 分频参数 | 避免沿用原先 32768Hz 的参数，只作为近似显示 |
| 使用独立标记 0x4C53，并检查实际来源与使能位 | 避免旧 0x5050 标记让新程序跳过 LSI 配置 |
| 必要时 BKP_DeInit，再设置时钟与示例日期 | 切换 RTC 时钟源要求复位备份域；会清旧时间与所有备份寄存器，不是仅清一个标记 |
| 每次启动开启 LSI，已有效配置时不再主动 RTC_Set | 系统复位后需要重新开启 LSI；不能把不重复设置时间等同于真正无缝走时 |
| 初始化阶段的等待加入超时，main 检查返回值并输出错误 | 原 LSE 等待的超时判断写在循环外，无法救出一直未就绪的循环；非零返回不继续输出伪正常日期 |
| KEY_Init 前开启 AFIO | 这是 PB4/JTAG 配置的初始化顺序配套修正，不是选择 LSI 本身的必需步骤 |
| hd 启动文件改为 md，独立源文件和 OBJ_LSI | 与原工程 C8/MD 目标匹配，避免混淆原版和新固件 |

原工程、原始编码和声明保留。当前目标编译 main_lsi.c、rtc_lsi.c 与 md 启动文件；原 main.c、rtc.c 仅作对照。初始化等待有限时处理，不宣称中断等所有代码中的等待均已重写或全程序已完成健壮性验证。

## 6. RTC_Init 与保时的边界

示例时间为 2024-04-01 16:29:00，并非电脑现实时间。有效初始化标记控制是否设置初始时间；每次启动都无条件 RTC_Set 会重设时间。修改日期参数后已有标记可能令设置分支不再执行，不能凭改参数就认为立刻生效。

备用电池只为相应备份域提供条件，不意味着 CPU 在主电源断开时继续跑主程序。本次使用 LSI，不记录为 LSE/VBAT 断电连续计时成功；未连接电池，不进行电池充电实验。手册所谓二极管电源切换电路“给电池缓充”的说法不能照搬，非充电型纽扣电池不可充电。
