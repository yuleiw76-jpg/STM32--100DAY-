## 3. ADC时钟与F103适配

最终配置：HSE按8MHz使用，PLL×9，SYSCLK/HCLK为72MHz；PCLK2为72MHz，ADC预分频为6，所以ADC时钟为12MHz。F103 ADC上限为14MHz，不能沿用先前/2得到的36MHz。CubeMX弹窗是时钟约束提示，不代表硬件已经损坏。

F103的ADC为12位，本例右对齐，正常结果范围0～4095。手册中F407可配置的Resolution、EOC Selection、DMA Continuous Requests等项目，不能要求F103界面逐项长得一样。采样周期也要按F103支持的选项选择。

最终双通道参数见[adc.c](Code/2026-10-17_HAL_ADC_GPIO_EXTI/Core/Src/adc.c)：

| 参数 | 最终值 |
| --- | --- |
| 外设 | ADC1 |
| 通道与顺序 | PA0/IN0/Rank1，PA1/IN1/Rank2 |
| ScanConvMode | ADC_SCAN_ENABLE |
| ContinuousConvMode | DISABLE |
| DiscontinuousConvMode | ENABLE |
| NbrOfDiscConversion | 1，每次触发转换一个Rank |
| NbrOfConversion | 2 |
| 触发 | ADC_SOFTWARE_START |
| 对齐 | ADC_DATAALIGN_RIGHT |
| 两路采样周期 | 239.5 Cycles；第二路沿用同一个sConfig中的SamplingTime |

Rank表示序列中的转换先后，不是NVIC抢占优先级。输入引脚启用和转换序列配置是两件事；勾选两个IN后还要核对转换数、Rank及扫描模式。

## 4. EOC、DR与轮询

以下解释是对手册的补充和F103适配，不把F407的行为直接说成所有STM32都相同。

- EOC是End Of Conversion，表示转换完成，不是CPU已经读取完成。
- DR是ADC结果寄存器。硬件完成转换后本来就会写DR，不是设置EOC后才开始写。
- HAL_ADC_GetValue(&hadc1)读取ADC1的DR并返回数值；赋值语句再把它保存到RAM变量。
- 未读结果被下一次结果覆盖，是数据未及时转存，不是某一个12位数值太大装不进DR。
- 在手册F407的轮询思路里，如果等整个序列结束才读唯一DR，早期通道结果可能已经被后续通道覆盖；每通道EOC提供及时读取的机会，但ADC不会因此自动等CPU。
- EOC不是访问DR的权限锁；程序可以读取DR，但未确认转换完成时可能读到旧值。
- 间断模式不等于CPU中断。它控制ADC序列每次触发前进多少个Rank，本实验不依赖ADC中断回调。

本地F1 HAL在扫描模式下的HAL_ADC_PollForConversion走估计转换时间等待分支，不能把当前方案描述成“每调用一次都等待一个通道EOC”。[F1 HAL头文件](Code/2026-10-17_HAL_ADC_GPIO_EXTI/Drivers/STM32F1xx_HAL_Driver/Inc/stm32f1xx_hal_adc.h)明确给出扫描轮询配合间断、每次一个转换的支持方式；具体实现见[HAL ADC源码](Code/2026-10-17_HAL_ADC_GPIO_EXTI/Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_adc.c)。

## 5. 当前双通道应用流程

初始化完成后、首次Start之前进行一次HAL_ADCEx_Calibration_Start。主循环保留原来的定时器和LED实验，只新增ADC与GPIO读取，没有为归档删改旧功能。

```c
uint8_t i;
for (i = 0; i < 2; i++)
{
    if (HAL_ADC_Start(&hadc1) != HAL_OK) { break; }
    if (HAL_ADC_PollForConversion(&hadc1, 100) != HAL_OK) { break; }
    adc_value[i] = (uint16_t)HAL_ADC_GetValue(&hadc1);
}
HAL_ADC_Stop(&hadc1);
pa5_level = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_5);
```

这里Start在循环里面，Stop在两次转换之后，不在两个Rank之间Stop。校准只在初始化后做一次，不放进每轮读取。

100是传给轮询函数的超时参数，不是“每次固定采样100ms”；当前F1扫描等待实现还要按上一节所述区分。主循环仍有两次800ms延时，变量约每1.6秒更新一次。Ozone图中的100Hz是电脑端变量采样设置，不会把应用实际读取频率变成100Hz，也不是ADC硬件时钟。

当前快照为最终双通道版，单通道阶段的验证由截图和记录保留，没有单独伪造一个“当时已验证”的8.1工程快照。

## 7. GPIO输入与外部中断

普通输入返回高/低状态，不是ADC模拟量。上拉通过内部电阻提供默认高电平，外部接GND仍可拉低。无上下拉只表示内部没有偏置，是否悬空还取决于外部是否驱动。

PA5普通上拉输入实验已通过：接地0，断开1。最终改为EXTI后仍可用HAL_GPIO_ReadPin读取电平，但轮询电平不证明中断进入。

| 引脚 | 当前触发沿与偏置 | NVIC入口 | 验证状态 |
| --- | --- | --- | --- |
| PA4 | 上升沿，上拉 | EXTI4_IRQn | 配置、回调及编译通过；未实测 |
| PA5 | 上升沿，上拉 | EXTI9_5_IRQn | 配置、回调及编译通过；未实测 |
| PB12 | 上升沿，上拉 | EXTI15_10_IRQn | 配置、回调及编译通过；未实测 |

三个NVIC入口优先级均为0,0；IRQ函数分别调用HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_4/5/12)。HAL检查并清除pending位后调用用户HAL_GPIO_EXTI_Callback。PA3留给USART2_RX，因此使用PA4替代手册中的PA3。

曾建议分别配置上升、下降、双边沿，但最终生成源码全是上升沿。本次记录以最终保存代码为准：它覆盖三个IRQ分组，不声称比较了三种触发沿。

回调位于main()之外的USER CODE BEGIN 4区域，按GPIO_Pin区分4、5、12，再读高电平后翻转PC13。主循环也每800ms写PC13，所以不能单靠LED观察把中断触发判为通过。若以后自愿验证，可用断点或独立计数；本次用户明确不做，不列为本轮继续任务。

## 9. 安全和归档边界

- GPIO/ADC只使用确认过的板上3.3V与GND，不能把5V直接送入本次ADC；换线先断电，避免误接相邻输出或供电引脚。
- 中断回调保持短小，不加入HAL_Delay。当前EXTI优先级0、SysTick优先级15，若在EXTI内等待依赖SysTick的延时，SysTick不能抢占它，可能无法结束等待。
- TIM1仍为零死区、Break禁用，只有MCU逻辑波形验证，不是可直接接功率桥/电机的成品方案。
