## 接线与数据路径

下表对应手册接线表和当前工程配置；不是对每条实物连接的独立电气测量。

| 连接 | 对应功能 |
| --- | --- |
| 按键模块 K1 ↔ PB4 | EXTI4，输出 `4` |
| 按键模块 K2 ↔ PB5 | EXTI5，输出 `5` |
| 按键模块 K3 ↔ PB11 | EXTI11，输出 `11` |
| 按键模块 GND ↔ 单片机 GND | 按下后将对应输入接地 |
| USB 转 TTL 模块 GND ↔ 单片机 GND | 共地 |
| 模块 TXD ↔ PA10（USART1_RX） | 电脑向单片机发送；本节按键输出主路径未使用此方向 |
| 模块 RXD ↔ PA9（USART1_TX） | 单片机向电脑发送 |
| 模块 USB ↔ 电脑 USB | XCOM 串口接口 |

```text
按键按下 → 上拉输入由高变低 → EXTI 下降沿请求
         → CPU 执行中断服务函数 → printf → USART1 → 电脑 XCOM
```

串口设置为 `9600、8N1`：9600 波特率、8 数据位、无奇偶校验、1 停止位。改线先断电；保持共地，并使用与板卡兼容的供电方式和 TTL 电平。不要把接线表未列出 VCC 理解为任意供电连接都可用。

## 核心理解

### 1. 不再依赖主循环扫描按键

旧按键实验在主循环中调用扫描函数；本例的 `main()` 不调用 `KEY_Scan()`，由 EXTI 硬件检测指定引脚的电平跳变，再向 CPU 请求中断。主循环中的 `delay_ms(100)` 不是每100毫秒扫描一次按键。

输入持续保持低电平，不会凭空再产生新的下降沿。但不能据此保证机械按键一次操作绝对只有一次请求，因为实际按键可能抖动；中断挂起标志也必须正确处理。

补充知识：外部中断不是另一个 CPU。硬件负责检测，CPU 仍要执行中断服务函数；关中断、优先级和其他中断的执行时间都会影响响应。轮询并非一律不能用，应按任务需求选择。

### 2. GPIO 来源、EXTI 线与服务函数要分开

| GPIO 来源 | EXTI 线 | 中断服务函数 |
| --- | --- | --- |
| PB4 | EXTI4 | `EXTI4_IRQHandler` |
| PB5 | EXTI5 | `EXTI9_5_IRQHandler` |
| PB11 | EXTI11 | `EXTI15_10_IRQHandler` |

同一编号的 EXTI GPIO 线，同一时刻只能选择一个 GPIO 端口来源。例如 PA5 和 PB5 都是 EXTI5 的候选来源，不能同时作为两条独立的 EXTI5 GPIO 中断来源。

若把 PB4 改为 PA4，来源配置要改成：

```c
GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource4);
```

EXTI 线仍是 `EXTI_Line4`。端口字母决定选哪一组 GPIO，数字决定选哪一条 EXTI GPIO 线。

EXTI0～4 各有独立中断入口；EXTI5～9 共用 `EXTI9_5_IRQHandler`，EXTI10～15 共用 `EXTI15_10_IRQHandler`。共用入口不代表它们共用同一个挂起标志。

### 3. 初始化代码的分工

| 代码位置 | 作用 |
| --- | --- |
| `KEY_Init()` | PB4、PB5、PB11 配置为上拉输入，关闭 JTAG、保留 SWD |
| `GPIO_EXTILineConfig(...)` | 通过 AFIO 选择对应 EXTI 线的 GPIO 来源 |
| `EXTI_Line` | 指定要配置的 EXTI 线 |
| `EXTI_Mode_Interrupt` | 选择中断模式 |
| `EXTI_Trigger_Falling` | 选择下降沿触发 |
| `EXTI_LineCmd = ENABLE` | 开启该 EXTI 线 |
| `EXTI_Init(...)` | 将结构体字段应用到 EXTI 配置 |
| `NVIC_Init(...)` | 配置并使能对应 CPU 中断通道 |

GPIO 仍使用 `GPIO_Mode_IPU`，不是因为使用 EXTI 就改成复用推挽输出。AFIO 的来源选择与 GPIO 的输入/输出模式是不同的配置。

### 4. 消抖、复查电平与清除挂起标志

以 PB4 为例，当前工程的处理顺序是：

```c
delay_ms(10);
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_4) == 0)
{
    printf("4\r\n");
}
EXTI_ClearITPendingBit(EXTI_Line4);
```

先延时，再确认输入仍然为低，才发送按键编号。如果10毫秒后已经恢复高电平，`printf` 不执行，但位于 `if` 外面的清除挂起标志仍会执行。这个问题已经正确回答。

清除挂起标志，是清除这次请求的记录，不是把引脚电平改为高，也不是关闭中断。库函数通过向 EXTI 的对应挂起位写1来清除；可查看[当前工程的库函数实现](Code/STM32F10x_FWLib/src/stm32f10x_exti.c)。

补充知识：中断中延时10毫秒、直接调用 `printf` 是本例便于学习的简单做法，不是复杂系统的通用最佳方案；它们会延长服务函数占用 CPU 的时间。以后若同一共享入口启用多条 EXTI 线，应先检查各线的挂起状态，再分别处理和清除，不能只靠引脚当前是低电平判断请求来源。

### 5. 本工程的中断优先级

主程序设置 `NVIC_PriorityGroup_2`。以下填写值来自实际源码，部分原注释与字段值不一致，以字段值为准。

| 通道 | 抢占优先级字段 | 子优先级字段 |
| --- | --- | --- |
| EXTI4_IRQn | 2 | 2 |
| EXTI9_5_IRQn | 2 | 1 |
| EXTI15_10_IRQn | 2 | 0 |

三者抢占优先级相同，不能凭子优先级不同就认为可以互相抢占。子优先级用于同时等待时的选择；本次没有专门实验测量其排序或中断嵌套行为。

## 补充检查：AFIO 时钟初始化顺序

`KEY_Init()` 中的 `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)` 配置 AFIO，以关闭 JTAG、保留 SWD，释放 PB4 等 JTAG 引脚。ST 参考手册要求访问 AFIO 配置寄存器前先使能 AFIO 时钟。[ST RM0008，9.4 节](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)

用户在 `main()` 中、`KEY_Init()` 之前新增：

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);
KEY_Init();
EXTIX_Init();
```

`EXTIX_Init()` 内原有的 AFIO 时钟使能保留。重复使能不关闭该时钟。

重要区别：修改前、修改后都出现预期结果。本次调整属于补齐初始化前置条件，不是已证明的故障修复。静态初始化顺序不能直接代替运行时寄存器证据；未确认原版在该测试环境下也有效的底层原因，不宣称是下载器代为配置或保留了上次设置。
