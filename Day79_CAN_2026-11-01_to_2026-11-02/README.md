## 关键配置

| 项目 | 保存的设置 |
| --- | --- |
| MCU | STM32F103C8T6；工程器件STM32F103C8、宏STM32F103xB |
| CAN模式 / 时钟 | Normal；APB1为36MHz |
| 位时序 | Prescaler=4、BS1=6TQ、BS2=2TQ、SJW=1TQ |
| 计算位速率 | 36MHz ÷ [4 × (1+6+2)] = **1Mbps**；未测波形 |
| 引脚 | PB8接收、PB9发送；已生成CAN重映射调用 |
| 自动功能 | Automatic Bus-Off Management、Automatic Retransmission启用 |
| 接收 | FIFO0中断已启用；中断入口调用HAL_CAN_IRQHandler |
| 过滤 | 32位掩码模式，设定ID和掩码全0，分配FIFO0并激活 |
| 发送帧 | 标准数据帧，ID=0x001，DLC=8 |

全0掩码用于放开过滤，**不是只接收ID=0或只接收标准数据帧**；发送报文头与接收过滤条件分别配置。

## 今天理清的代码连接

TIM2回调置`can_1khz_flag`；main检查并清除标志、更新`TxData[0]`，邮箱空闲时提交发送请求。接收回调成功调用`HAL_CAN_GetRxMessage()`后才设置`can_rx_flag`。

TIM2配置可计算为1kHz更新，但**没有验证实际CAN发送频率为1kHz**：旧ADC轮询仍保留，软件标志也不保存累计事件次数，邮箱忙时本轮不会提交发送请求。

配置过程中曾因BS1保留默认值1而出现位速率过高的报错，经讨论后调整。今天明确位速率由时钟、分频及总TQ共同决定，不能只看分频。
