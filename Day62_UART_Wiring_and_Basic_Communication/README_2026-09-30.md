## 三、代码功能对应

### PB4：STM32向电脑发送普通文本

`PB4` 被拉低后，程序会发送：

```text
Hello!
1
```

OLED同时显示源码中的 `Sessage sent.`。其中 `Sessage` 是原代码里的拼写，不是串口故障。

### PB5：发送串口绘图数据

`PB5` 被拉低后，程序先发送 `0～999`，再发送 `1000～1`，可供串口绘图软件显示往返变化的曲线。

这不是明天的最低验收要求；基本双向收发成功后还有时间再测。

### 电脑向STM32发送字符串

USART1每收到一个字节都会进入接收中断。当前程序以 `\r\n` 作为一条消息的结束标志，接收完成后会：

```text
复制接收缓冲区
→ 翻转LED状态
→ 清空OLED
→ 在OLED显示收到的字符串
→ 清除状态和缓冲区
```

由于主函数中的 `text` 只有 20 字节，明天只发送不超过 19 个字节的英文或数字短字符串，并在串口助手中启用“发送新行/CRLF”。暂不发送中文。

## 四、USB转TTL模块

手中的模块为：

```text
MCS-81 V4 Isolated USB To TTL UART
```

其中：

- `TX`：普通串口发送端，本实验使用；
- `RX`：普通串口接收端，本实验使用；
- `GND`：TTL侧参考地，必须连接STM32的GND；
- `TX-D`：由TX经二极管引出的特殊开漏信号，主要用于特定单片机下载，本实验不接。

接入STM32之前，仍需确认模块TTL侧工作在 `3.3V`。可先让模块只插电脑，用万用表测量空闲状态下 `TX` 对 `GND` 的电压：

- 约 `3.3V`：可以继续连接；
- 约 `5V`：停止连接，先调整电平选择；
- 约 `0V`：先检查隔离侧供电或跳帽，不直接接STM32。

## 五、明日接线表

### USB转TTL与STM32

UART发送端要连接对方的接收端：

| USB转TTL | STM32 |
| --- | --- |
| `TX` | `PA10/RX` |
| `RX` | `PA9/TX` |
| `GND` | `GND` |
| `TX-D` | 不接 |

STM32如果已经通过原有方式供电，USB转TTL模块的 `5V、3.3V、VCC` 暂时都不接。

### OLED与STM32

| OLED | STM32 |
| --- | --- |
| `GND` | `GND` |
| `VCC` | `3.3V` |
| `SCL` | `PA6` |
| `SDA` | `PA7` |

### 临时替代按钮

`key.c` 将 `PB4` 和 `PB5` 配置成内部上拉输入，按下时检测低电平。因此可以用一根杜邦线模拟按钮：

```text
杜邦线一端接GND
另一端短暂接触PB4或PB5
触发后立即松开
```

- `PB4` 瞬时接GND：代替K1；
- `PB5` 瞬时接GND：代替K2。

不要让杜邦线误碰 `3.3V` 或其他电源引脚。
