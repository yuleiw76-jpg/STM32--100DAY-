# Day34_MPU6050_Balance_Car_Integration

## 1. 今日目标

今天将 Day33 已经单独验证成功的真正 MPU6050 驱动移植到平衡小车工程中，确认传感器、DMP、串口和直立环能够在完整小车系统内共同运行，并重新进入直立环 PID 调参。

主要目标：

- 将 `WHO_AM_I=0x68` 的真正 MPU6050 接入平衡小车；
- 保留原有电机、编码器、定时器和 PID 工程结构；
- 验证 MPU6050 初始化、DMP 初始化和姿态角读取；
- 使用 CH340 USB 转 TTL 观察启动信息；
- 确认小车前倾、后倾时两个电机的纠偏方向；
- 关闭速度环，只调直立环的 P 参数。

## 2. Hardware

- MCU：STM32F103C8T6
- IMU：MPU6050，`WHO_AM_I=0x68`
- 电机驱动：L298N
- 电机：两路直流减速电机
- 调试器：J-Link
- 串口模块：CH340 USB 转 TTL
- 电源：12V 锂电池组

## 3. 接线

### MPU6050

| MPU6050 | STM32F103C8T6 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| SCL | PA4 |
| SDA | PA5 |

### USB 转 TTL

| USB 转 TTL | STM32F103C8T6 |
| --- | --- |
| RX | PA9（USART1 TX） |
| GND | GND |

串口参数为 `115200 8N1`，即波特率 115200、8 个数据位、无校验、1 个停止位、无流控。STM32 已经独立供电时，不再使用 USB 转 TTL 的 VCC 重复供电。

## 4. 移植与验证过程

1. 在 Day34 副本中替换 MPU6050、软件 I2C 和 DMP 相关驱动，未直接修改以前的成功工程。
2. 保持 MPU6050 使用 PA4/PA5 软件 I2C，不修改小车原有硬件接线。
3. 将芯片身份判断恢复为真正 MPU6050 的 `WHO_AM_I=0x68`。
4. 编译工程，确认 Keil 可以正常生成固件。
5. 下载到 STM32 后，通过串口检查初始化状态。
6. 在 Keil Debug Watch 中观察 `Pitch`、`Roll`、`Yaw` 和 `gyro[1]`，确认 DMP 姿态数据能够更新。
7. 排查串口只收到 48 B 后停止的问题，最终确认主要原因仍是面包板和杜邦线接触不稳定。
8. 保持速度环关闭，只让直立环输出控制两个电机。

## 5. 验证结果

串口启动信息：

```text
WHO_AM_I=0x68
MPU INIT OK
DMP INIT OK, 200HZ
```

最终确认：

- MPU6050 身份读取正确；
- MPU6050 初始化成功；
- DMP 初始化成功，采样频率为 200 Hz；
- Pitch、Roll、Yaw 在 Keil Watch 中可以正常更新；
- 两个电机能够同步工作；
- 小车前倾和后倾时，电机纠偏方向相反且方向正确；
- 串口空白并不是程序停止，而是面包板接触不稳导致 TX/GND 连接中断。

## 6. 当前直立环状态

今天结束时，磁盘中实际保存的参数为：

```c
static float P = 700;
static float I = 0;
static float D = 0;
float aim_pitch = 0.3f;
```

控制状态：

- 速度环暂时关闭，`pidv=0.0f`；
- 电机只使用直立环输出，调用为 `go((int)-pidp, 0)`；
- 当前只调 P，尚未加入 D；
- 放手后小车会出现幅度较大的来回摆动。

这说明 P 已经能够产生纠偏力，但系统阻尼不足。下一步不再大幅增加 P，而是在保持当前 P 附近的基础上逐步加入 D，观察摆动次数和振幅是否下降。

## 7. 调试记录

### 7.1 串口没有输出

现象：串口助手显示端口已打开，但接收计数停在 48 B，复位后也不再继续输出。

排查：

- Keil 可以正常下载；
- Debug Watch 中 Pitch、Roll、Yaw 正常变化；
- 初始化日志曾经成功输出，说明波特率和程序配置基本正确；
- 重新压紧面包板与杜邦线后，串口恢复连续输出。

结论：接触不良会让系统表现得像软件故障，必须先检查供电、共地和信号线的物理连接。

### 7.2 平衡角重新确认

今天重新观察小车机械直立位置，对目标角进行了调整。最终保存值为：

```c
aim_pitch = 0.3f;
```

该值来自当前小车结构和 MPU6050 安装姿态，后续如果重新移动传感器或机械结构，需要再次测量，不能直接照搬旧值。

## 8. 工程说明

Keil 工程文件：

```text
Code/Balance_Car_MPU6500_DMP_Fixed/USER/LED.uvprojx
```

虽然内部文件夹名仍保留历史名称 `MPU6500_DMP_Fixed`，但当前驱动和身份判断已经按真正的 MPU6050（`WHO_AM_I=0x68`）运行。保留文件夹名是为了避免在调参阶段引入不必要的路径变化。

主要目录：

- `USER/`：主程序、Keil 工程和中断文件；
- `HARDWARE/MPU6050/`：MPU6050、软件 I2C 和 DMP 驱动；
- `HARDWARE/PID/`：直立环与速度环代码；
- `HARDWARE/MOTOR/`、`PWM/`、`ENCODE/`、`TIM/`：电机控制、PWM、编码器和控制周期；
- `SYSTEM/`：延时、系统与串口驱动；
- `CORE/`、`STM32F10x_FWLib/`：启动文件、CMSIS 与标准外设库。

Keil 最新构建记录：

```text
0 Error(s), 2 Warning(s)
```

工程目标芯片为 `STM32F103C8`，下载调试器配置为 `J-Link`。

## 9. Learning Summary

今天完成了从“单独验证 MPU6050”到“接入完整平衡小车”的关键一步。真正的 MPU6050 能够稳定通过 `WHO_AM_I`、DMP 和姿态数据验证，说明现在终于具备继续 PID 调参的可靠数据基础。

这次也再次体会到：嵌入式调试不能只看代码。即使程序、串口参数和 Debug 数据都正常，一根松动的面包板连接也会造成串口中断、模块不亮或初始化失败。以后遇到异常时，应按照供电、共地、接线、通信、数据、控制算法的顺序逐层排查。
